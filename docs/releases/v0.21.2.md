# Lore v0.21.2 — 2026-10-05

## v0.21.2

### What changed

- **The agent's system prompt is editable** in Admin → Agent, with Save and Reset. The next turn in every project uses the new text; Reset restores the shipped default. The text must keep the `{embed_schemes}` token exactly once. The Agent tab now comes before Tools.
- **Embedding calibration sits next to the embedding model**: Models → Embedding calibration holds the query instruction, the retrieval score floor, the duplicate-fact similarity and the merge-candidate floor.
- **Eleven search, indexing and memory limits are editable live** — embedding timeout, chunk size and input ceiling; memory facts and chunks per search; token budgets for documents, references and memory; project-memory merge candidates and budgets. Each setting explains what it does, which way to turn it and when it takes effect.
- **The "Query rewrite" section in Admin → Search is gone.** It never affected results; search behaves exactly as before.
- ComfyUI and MCP gateway settings are reordered and described in plain language.
- The README links the companion LLM API Gateway and STT API Server, and `scripts/search-tuning/` lets you re-derive the score floor and drop-off after switching embedding models.

### Upgrading

```sh
curl -O https://raw.githubusercontent.com/kreolsky/lore-knowledge-creator/main/docker-compose.yml
docker compose pull --ignore-buildable
docker compose up -d --build
```

`--ignore-buildable` skips the agent and sandbox images in `pull`: they are not published, `up --build` builds them from source. Without the flag `pull` reports *pull access denied* for `lore-harness`, `lore-sandbox` and `lore-sandbox-gw` — harmless, the update still works.

All three lines are needed, as in the README → Update: skipping a release means skipping its compose file too, and an install older than v0.21.0 does not start on these images without the new one.

- No new `.env` keys; new settings default to the previous built-in values.
- No database migration.

## v0.21.1

### What changed

- **Deleting a project is instant.** Only the project itself is marked deleted; its documents, references and chats keep their own state, and they no longer appear anywhere — public share links answer 404, widget keys answer 410, embeddings and admin pages skip them.
- **Large projects: `ref:` links work past the 1000th reference.** Links no longer render as broken, a click opens the reference instead of "not found", and the `ref:` suggestions search titles on the server.
- **A reference's hover preview shows its latest saved body**, not the one from when the tab was opened.
- **Admin panel → Info** shows how big the database is on disk and how much data is marked deleted, table by table. The collapsed project card shows the owner's name again.
- **More resilient database connection.** The backend recovers on its own when its connection to SurrealDB drops, instead of failing requests until a restart.
- **Fewer settings.** Seven purely internal tuning knobs are no longer shown in the admin panel. Upload size limits have built-in defaults (audio 500 MB, images and Markdown 50 MB) and no longer need to be set.

## v0.21.0

### What changed

- **Install with one file, no `.env`.** Download `docker-compose.yml`, run `docker compose up -d`, sign in as the preset admin, and set the AI API URL, key and models in Admin panel → Models & APIs. Everything — the agent, embeddings, speech recognition, session titles, web search — works from the next message, with no restart. The database password and the agent's internal secret are generated on first start and kept in the `secrets` volume.
- **The admin panel shows only what you configure.** The Infrastructure section is gone. The session cookie is marked Secure automatically when the browser comes over HTTPS (your proxy must send `X-Forwarded-Proto`, see [self-hosting](../self-hosting.md)). The running version is shown in the header: "Admin panel (v0.21.0) : …".
- **Settings are grouped where you look for them:** Models & APIs → Search → Tools → Agent → Storage. Web search now lives in the Search tab, next to retrieval and query rewrite. STT and ComfyUI concurrency sit with their services.
- **A safer agent sandbox.** Its network boundary moved into a separate `sandbox-gw` container that the sandbox cannot change, even as root. The sandbox's SSH key is generated on first start.
- **Chat:** a message sent while the agent is answering waits in a queue and goes out when the turn ends; reloading mid-answer keeps the text already shown; with no models available the chat says so instead of offering an input that cannot send.
- **Projects:** a built-in "Lore guide" section in every project that the agent reads when asked how Lore works; project descriptions; manual ordering of references; a title on every preview popup.

### Upgrading

The compose file changed (new `secrets-init` and `sandbox-gw` services), so download it again:


`--ignore-buildable` skips the agent and sandbox images in `pull`: they are not published, `up --build` builds them from source. Without the flag `pull` reports *pull access denied* for `lore-harness`, `lore-sandbox` and `lore-sandbox-gw` — harmless, the update still works.

`--build` is required: the agent and its sandbox are built from source.

- Requires Docker Engine 26.0+ and Docker Compose v2.26.0+.
- The settings below were removed and are ignored if still in your `.env`: `COOKIE_SECURE` (now automatic), `LORE_SECRET_KEY`, `HARNESS_DRIVER_SECRET`, `HARNESS_MODEL`, `SURREAL_*`, `TURN_TIMEOUT_S` (use `TURN_PROGRESS_GRACE_S`). If you had set `LORE_SECRET_KEY`, everyone is signed out once after the upgrade.
- If you set AI settings in `.env`, they still work as defaults; a value set in the admin panel wins.
- This release migrates the database — back up first; a rollback past this release needs the backup.
