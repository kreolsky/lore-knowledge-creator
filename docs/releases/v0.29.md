# Lore v0.29

## Upgrading from 0.28 or earlier

```sh
curl -O https://raw.githubusercontent.com/kreolsky/lore-knowledge-creator/main/docker-compose.yml
docker compose pull --ignore-buildable
docker compose up -d --build
```

Required:

- Migrates the database (v0.29.0, v0.29.1) — back up first; a rollback past this release needs the backup. The old `is_public` / group audience fields are removed, the user tier is added and `ai` is backfilled for existing users.
- Access change: a public project owned by a non-admin becomes readable by the owner's group only (or private if the owner has no group). Admin-owned public projects stay public.

Optional:

- New `.env` keys: `COMPOSE_PROFILES=router` (bundled router, off by default), `WEB_SEARCH_MODEL` (only for the `router` search provider; defaults to the chat model).

No `.env` keys removed in 0.29.

Coming from an older minor: read its note in this folder too, and follow every migration and required step.

## What changed

### v0.29.2

- Editor: a read-only user can no longer tick task-list checkboxes (`- [ ]`). A click on a checkbox changes the document only when the editor is editable; viewers, previews and transclusions show the checkbox without letting it toggle.

### v0.29.1

- Account capability tiers: every user has a tier — `base` (documents only), `voice` (+ speech-to-text) or `ai` (+ chat, extractors, schedules, image generation). Admins and moderators set it when creating or inviting a user and in the user edit panel. The server enforces it on every costly start in any project; the UI hides what the tier does not allow and explains a refusal. Admins always have every capability. Existing users are upgraded to `ai`, so nobody loses a feature.
- Admin → Model access: drag models to order them; the chat and utility model pickers follow that order.
- Chat: prompt rail ticks render evenly at any browser zoom and preview the jump target on hover; a failure inside the response stream now shows a warning instead of being swallowed.
- Recording: a recording-cache failure during a take shows one warning; the take still uploads.
- Notes: the note connector follows its anchor while you type above it.
- Mobile: swiping the document tree or the references list scrolls instead of starting a drag-reorder.

### v0.29.0

- Projects can be opened to a whole group. A project now carries one list of audiences — all logged-in users, a moderator's group or an admin group — each with its own access level; a member's effective access is the highest of their own row and every matching audience.
- An owner in a group sets the level for their own group; an admin edits the full list. Making a project public to all users is now admin-only.
- Owners in a group invite from the group's roster through one filterable picker; the picker hides people already in the project and disables levels the group already grants. A member row below the group's level shows the level that actually applies.
- Access changes reach open documents immediately; revoking access in one project no longer closes the user's documents in another.
- Chat: a prompt rail on the right edge lists all your prompts and jumps to any of them; it replaces the "previous message" button.
- Web search can go through your AI router (provider `router`, Anthropic Messages with the native web search tool); `WEB_SEARCH_MODEL` picks the model and defaults to the chat model. Fixed: search providers could fail with "the credentials service is not composed".
- Optional bundled LLM router: set `COMPOSE_PROFILES=router` and configure it under `router/config/` (examples in `router/config.example/`). Without the profile nothing changes. See `self-hosting.md`.
- Admin: the user edit panel stays open after Save with a "Saved" mark; the project "Add user" picker is filterable.
