# Lore v0.33

## Upgrading from 0.32 or earlier

```sh
curl -O https://raw.githubusercontent.com/kreolsky/lore-knowledge-creator/main/docker-compose.yml
docker compose pull --ignore-buildable
docker compose up -d --build
```

Required:

- Migrates the database (v0.33.0) — back up first; a rollback past this release needs the backup.

Optional:

- After upgrading to v0.33.1, run once: `docker compose exec backend python -m migrations.backfill_edge_kinds`. It records whether each link is a mention or an embed; until it runs, every existing link reads as a mention.
- Back up the new file `.lore/user_secrets_key` in your data directory together with the database. It is created on first use and encrypts personal keys; without it users have to enter their keys again.

No new `.env` key and no compose change in 0.33.

Coming from an older minor: read its note in this folder too, and follow every migration and required step.

## What changed

### v0.33.1

- The links panel shows incoming and outgoing links grouped by kind (mention, embed), each group in its own section with hover previews. A deleted document stays in the panels that linked to it, as a broken link.
- Showing notes and chats in the links panel is now a project setting (Display settings).
- The assistant can read a document's links in both directions with `get_links`.
- Markdown pipe tables become editable table objects on every import and when the assistant writes them. Tables pasted from Google Docs, Sheets and Excel do too, with merged cells unfolded.
- New tables get column widths that follow their content. Tab in the last cell adds a row.
- The `/api/documents/{id}/backlinks` endpoint is removed; use `/api/documents/{id}/edges`.

### v0.33.0

- Personal keys: each user stores API keys in their profile, encrypted and bound to hosts. The agent calls external APIs with them through `http_request` without ever seeing the key, and every write asks for approval.
- Personal MCP servers: an admin connects an external MCP server and picks who holds the key (each user, one shared key, or none). Users paste their key and see at once whether it works. External tools are marked as such and ask for approval unless the server marks them read-only.
- Save facts from a chat: ask the assistant to save something to the project's knowledge and approve the proposed facts on one card. Facts link back to the chat and follow its document.
- Chat images are compressed once when attached, and that version is what you see and what the model receives — no more shrinking screenshots by hand.
- Custom theme colors in the profile, with JSON export and restore.
- The dashboard loads projects 50 at a time as you scroll; users with more than 50 projects no longer lose the oldest ones.
