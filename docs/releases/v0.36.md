# Lore v0.36

## Upgrading from 0.35 or earlier

```sh
curl -O https://raw.githubusercontent.com/kreolsky/lore-knowledge-creator/main/docker-compose.yml
docker compose pull --ignore-buildable
docker compose up -d --build
```

Required:

- Migrates the database (v0.36.0) — back up first; a rollback past this release needs the backup. Chats lose their pinned document context, and the Knowledge folder of the agent configuration moves into Rules. v0.36.1 also migrates (widens chat memory fields, no data loss). v0.36.7 migrates too: it deletes unused legacy fields from chats, projects, API keys and users, then makes nine tables strict — the deleted fields exist afterwards only in your backup.

No new `.env` key and no compose change in 0.36.

Coming from an older minor: read its note in this folder too, and follow every migration and required step.

## What changed

### v0.36.7

- Databases created by older versions get their nine core tables made strict once, after unused legacy fields are deleted from their rows. If any unexpected field remains, nothing is changed: the log names the field as an error and the next boot retries.

### v0.36.6

- Boot no longer changes any live schema definition, fields included — it renders the shipped schema into a scratch database and logs every difference as a warning. A change to an existing database's schema is always a release migration.

### v0.36.5

- Fixed: after upgrading to 0.36.4, projects could fail to open on databases whose tables predate their strict schema. Boot no longer changes table definitions; it only reports the difference. If you ran 0.36.4 and see this, upgrade — and contact the maintainers if projects still do not open, since 0.36.4 may already have changed those tables.

### v0.36.4

- Copying a selection with images and pasting it into Google Docs or Word now brings the pictures along. Pasting Lore content into a document of another project copies its images into that project instead of leaving dead links.
- Renaming behaves the same everywhere (documents, chats, references, tables, API keys, projects): Enter saves, Escape cancels, clicking away saves. Fixed a double save on Enter then click-away, and renaming a table from the breadcrumb renamed its document.
- The PIN lock says "too many attempts" when rate-limited instead of "connection error".
- On boot, edited table and field definitions in the schema now reach existing databases; a field lost outside Lore refuses boot and is named in the log.

### v0.36.3

- Group access to models survives: moving a model to Hidden or Tools parks its group grants instead of dropping them, and they come back when the model returns to Private or Public. While parked, the admin list shows the disabled checkboxes of the groups that will return. Admins can drag-reorder groups in the admin lists (visual only).
- The assistant can look at images attached to a document (image references) with a new view tool, under the same access rules as reading the document.
- Fixed: opening a document in a second window could blank out its tables until a reload.

### v0.36.2

- Admins see LLM token usage: every chat turn and background AI call is recorded, and an admin dashboard shows totals vs the previous period, a daily chart, user/group and model rankings, a source split and CSV export. Usage is kept for 365 days and counts from the upgrade on.
- Admins can upload an instance skill as a zip (SKILL.md with scripts and references); every user's assistant can use it, and each skill card lists its files.

### v0.36.1

- Fixed: chat memory failed to save on databases created before 0.36, so the assistant rebuilt the memory block every turn.
- A memory-on persona's chat shows its memory mark right after create, rename or branch, without a reload.
- Subagents can never do more than their parent: no write tools beyond the sandbox, no tools added after their creation. Research subagents' tool calls no longer fail.
- Table and structure tools move into the `tables` and `structure` skills; every assistant request is ~1.9k tokens lighter.

### v0.36.0

- Personas remember chats: the persona picked in a chat is its memory switch. A memory-on persona gets a table of contents for each of its chats, the assistant can read past chats' contents, and a new chat starts with a conversation-memory block. The chat shows which memory it received.
- The chat's persona appears in the chat list; the chat's table of contents appears in the prompt navigator.
- Agent configuration: Knowledge is folded into Rules; chat recall (read) and memory (write) are separate skills with their own off-switches; every assistant write under the system folder asks for confirmation.
- Chat header actions fold into a hover menu; chat controls sit above the input. A document link in an answer always opens in the center pane.
