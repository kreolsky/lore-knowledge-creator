# Lore v0.35

## Upgrading from 0.34 or earlier

0.35 moves the database to SurrealDB 4, which does not open a 3.x store in place. The store is moved by a dump and re-import, run once between `pull` and `up`:

```sh
curl -O https://raw.githubusercontent.com/kreolsky/lore-knowledge-creator/main/docker-compose.yml
docker compose pull --ignore-buildable
curl -O https://raw.githubusercontent.com/kreolsky/lore-knowledge-creator/main/scripts/surreal-rebuild.sh
mkdir -p backups
sudo env \
  STORE_DIR=/var/lib/docker/volumes/lore_surreal/_data/lore.db \
  PASS_FILE=/var/lib/docker/volumes/lore_secrets/_data/surreal/pass \
  SURREAL_CONTAINER=lore-surreal-1 \
  APP_CONTAINERS='lore-backend-1 lore-worker-1 lore-worker-transcription-1' \
  BACKUP_DIR="$PWD/backups" \
  COMPOSE='docker compose -p lore -f docker-compose.yml' \
  bash surreal-rebuild.sh --confirm --upgrade
docker compose up -d --build
```

Run it in the folder that holds `docker-compose.yml`, with the old release still running. If `.env` pins `LORE_VERSION`, set it to `v0.35.0` (or later) before `pull`. The paths above are Docker's defaults on Linux (`docker volume inspect lore_surreal` shows yours); the host needs `python3`. Lore is offline while it runs, roughly a minute per 100 MB of compressed dump.

What the script does: stops the app containers, dumps the database to `backups/`, counts every table, moves the old store aside as `lore.db.pre-rebuild-<timestamp>` inside the same volume, starts SurrealDB 4 on an empty store, imports the dump and compares the counts; success prints `parity OK`. On any failure it puts SurrealDB 3 back on the old store, restarts the apps and exits non-zero. In that case do not run the last line: your install is back on 0.34 as it was, and `up` would start SurrealDB 4 on the old store again. Set the surreal image in `docker-compose.yml` back to `surrealdb/surrealdb:v3.3.5` (or restore your old copy of the file), and open an issue with the script's output.

Do not set `SURREAL_EXPERIMENTAL_UPGRADE_FROM_3X`. SurrealDB 4 suggests it when it finds a 3.x store, but it converts the store in place, one way, and is not what this release is tested with.

### If you already ran the usual three update lines

Then SurrealDB 4 restarts in a loop with *"holds a SurrealKV v0.x database written by SurrealDB 3.x"*, the backend never starts, and the store is untouched. To recover:

1. In `docker-compose.yml`, set the surreal image to `surrealdb/surrealdb:v3.3.5` and run `docker compose up -d`. Lore 0.35 starts on the old database.
2. Set the image back to `surrealdb/surrealdb:v4.0.1`, without running `up`.
3. Run the block above from the `curl -O …/surreal-rebuild.sh` line on: the script, then `docker compose up -d --build`.

Required:

- Migrates the database (v0.35.0) — back up first; a rollback past this release needs the backup. The script's dump in `backups/` and the kept `lore.db.pre-rebuild-<timestamp>` are that backup; delete the kept store once 0.35 has run well for you.

No new `.env` key in 0.35.

Coming from a release older than 0.34: upgrade to 0.34 first (read its note in this folder and follow every migration and required step), then run the block above. SurrealDB 4 refuses to add the fields introduced since an older store's version, so a direct jump fails at the backend's schema step.

## What changed

### v0.35.0

- The database runs on SurrealDB 4.0.1.
- The assistant can list, read and diff a document's saved versions and restore one; the state before the restore is kept, so a restore can be undone. The same tools are available over the Tool API and MCP.
- Quote a selection into the chat (selection toolbar or Mod-J) with a link back to the passage; clicking such a link opens the document with the passage selected, also in public shares. Links to a passage count as links in the graph and survive export.
- "Work with selection" is gone: a chat is no longer confined to a selected span. Former pinned chats become ordinary chats.
- Optional sound when the assistant finishes or asks for confirmation: turn it on per project, pick a preset or upload your own in the profile.
- Ctrl+Alt+[ / ] changes the text column width, remembered per project.
- The MCP server check shows what the server actually answered.
- Fixes: the selection toolbar follows the text on scroll; cancelling the link picker no longer leaves `[text]()`; a markdown table pasted as plain text becomes a table; lists and quotes keep their indent inside table cells; a tab opened before an upgrade reloads instead of crashing; concurrent saves of one document no longer fail.
