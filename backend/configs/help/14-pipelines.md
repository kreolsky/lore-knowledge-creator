# Пайплайны

Пайплайн — автоматическая обработка материалов, привязанная к документу. Он работает в фоне и выдаёт результат в виде документа.

## Экстрактор

Сейчас в Lore один пайплайн — экстрактор. Он извлекает из материалов структурированную информацию и собирает из неё детерминированный отчёт: справочные данные, сводку по созвонам, заполненную форму.

Как настроить:

1. Опишите в отдельном документе, что и в каком виде извлекать (конфиг-документ). Агент поможет его составить: у него есть скилл настройки экстрактора.
2. Во вкладке «Референсы» документа с материалами, в разделе «Агенты», нажмите «Добавить агента». Выберите конфиг-документ и целевой документ, куда складывать результат.
3. Экстрактор запускается сам, когда готова расшифровка новой записи; другого события запуска пока нет. Вручную его можно запустить кнопкой «Отправить агенту» на карточке референса.

Можно задать шаблон заголовка результата (с датой, временем и названием документа) и модель.

Если обработка завершилась ошибкой, подробности появятся в системной заметке документа.

## Пометки по диапазонам и значениям

Экстрактор умеет сам помечать значения: «норма» или «выше нормы», цвет, жирное число. Для этого в конфиге заводится child-документ `ranges`, а в нём — таблица с тем же именем, что у переменной. Такая таблица привязывается к переменной.

Каждая строка таблицы — условие плюс пометки. Условия: `min` (значение не меньше), `max` (значение меньше) и `is` (значение из списка). Все остальные ключи строки — пометки, и каждая становится переменной шаблона `<имя переменной>_<ключ>`. Внутри пометки `{{value}}` подставляет само значение.

```yaml
uterus_length:
  - {flag: ниже нормы, view: "{{value}}",     max: 40}
  - {flag: норма,      view: "{{value}}",     min: 40, max: 60}
  - {flag: выше нормы, view: "**{{value}}**", min: 60}
  - {view: "{{value}}"}
```

В шаблоне пишите `{{uterus_length_view}} мм ({{uterus_length_flag}})`; для 72 получится «**72** мм (выше нормы)».

Строки проверяются сверху вниз, срабатывает первая подходящая. Строка без условий подходит всегда — ставьте её последней: она ловит всё, что не попало выше. Если пометки используют `{{value}}`, такая строка обязательна. Пустое значение или значение, не попавшее ни в одну строку, дают пустые пометки.

**Пометки по варианту из списка — `is`.** Для переменной с `type: enum` условие `is` перечисляет варианты из её `options`. Это всегда список, даже для одного варианта: `is: [укорочена]`, а не `is: укорочена`.

```yaml
cervix_state:
  - {is: [деформирована, укорочена], flag: патология}
  - {is: [норма], flag: норма}
  - {flag: ""}
```

Последняя строка без условий здесь оставляет пометку пустой: так значение, которого нет в списке, не получит чужую пометку.

**Разные нормы в зависимости от другой переменной — `by`.** Ключ `by` называет переменную-переключатель, остальные ключи — её значения, у каждого своя таблица. Для числа или да/нет это `"0"` и `"1"`, для варианта из списка — сам вариант.

```yaml
m_echo_thickness:
  by: postmenopause
  "0": [{flag: норма, max: 15}, {flag: выше нормы, min: 15}]
  "1": [{flag: норма, max: 5},  {flag: критично, min: 5}]
```

Если таблица, названная по переменной, написана с ошибкой (например, `is` без списка или нет последней строки без условий), обработка не запускается, а причина появляется в системной заметке «Pipeline Error» на документе. Подробную грамматику знает агент: попросите его настроить пометки.

Множественный выбор по умолчанию склеивается через запятую («A, B, C»); ключ `separator` в объявлении переменной задаёт свою строку между значениями (только для multiselect):

```yaml
access:
  type: multiselect
  options: [трансвагинальный, трансабдоминальный]
  separator: " и "
```

## В планах

- Запуск пайплайнов по расписанию из интерфейса (механизм уже есть, настройки в интерфейсе пока нет).
- Новые пайплайны, например саммаризация.
- Пайплайны, которые агент собирает сам, чтобы автоматизировать повторяющуюся работу.
